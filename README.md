# Smart Sender

Невеликий застосунок: вхід, список вебхуків і редагування. API імітує [MSW](https://mswjs.io/). Без UI плагінів для швидкості і ваги бандла. Проста архітектура, так я проект простий виносити одиничні файли в окрему папку немає сенсу в рамках цього проекту.

Як влаштований код: [documentations.html](./documentations.html).

## Запуск

```bash
npm install
npm run dev
```

Збірка і перегляд зібраного застосунку (мок увімкнений і там):

```bash
npm run build
npm run preview
```

Тест двух паралельних запитів (тільки цей тест, так як завдання інших не вимагало, то вони були скіпнуті):

```bash
npm test
```

## Ключові рішення

- `device_session_token` живе лише в пам'яті модуля. У `localStorage` лежить тільки `fingerprint` (32 hex-символи), у URL токен не потрапляє.
- Сесію зберігає мок у пам'яті, як аналог HttpOnly-cookie. Клієнт її не читає. Після перезавантаження сторінки потрібен повторний вхід; `page` і `search` лишаються в URL і застосовуються після входу.
- Усі заголовки, CSRF і повтори зібрані в `src/api/client.ts`. Перед іншими запитами клієнт читає `GET /csrf` і надсилає `X-CSRF-TOKEN` на POST і PUT. На 419 токен береться знову, запит повторюється один раз.
- Після 401 захищені запити ділять один `POST /auth/token/rotate` і повторюються один раз. Сам rotate цей шлях не запускає. Помилка rotate або повторний 401 завершують локальну сесію і повертають на вхід.
- React Query тримає лише кеш `/v1/me` і вебхуків. Повтори через Query вимкнені: їх робить HTTP-клієнт. Вихід викликає `/auth/token/revoke`, очищає пам'ять сесії і цей кеш.
- `page` та `search` зберігаються в query string, тому працюють перезавантаження і навігація назад/вперед. Зміна пошуку відкриває першу сторінку.
